# Codebase Structure

**Analysis Date:** 2026-09-12

## Directory Layout

```

│   ├── constants/       # Global constants, feature registries, plan definitions
│   ├── contexts/        # Global React Context providers
│   ├── hooks/           # Domain hooks for state, queries, hardware, and lifecycle
│   ├── integrations/    # Supabase client instantiation and generated types
│   ├── lib/             # Shared helper functions, sound utilities, and class merging
│   ├── pages/           # Top-level route pages rendered by the router
```

## Directory Purposes

**`src/components/`:**
- **Purpose:** Modular React components broken down by business capability and UI responsibility.
- **Contains:** Domain-specific folders containing presentation widgets, forms, dialogs, and table views.
- **Key subdirectories:**
  - `Admin/`: Restaurant management, user assignment, WhatsApp provider credentials.
  - `AI/`: Gemini chat interface and AI prompt capabilities.
  - `Analytics/`: Business intelligence dashboards, chart builders, time series analysis, metrics.
  - `Auth/`: Sign-in forms, route guards (`AppRoutes.tsx`, `PermissionGuard.tsx`, `SubscriptionGate.tsx`, `FeatureLock.tsx`).
  - `CRM/`: Customer profiles, loyalty tiers, points management, customer order history.
  - `Dashboard/`: Overview stats cards, customizable widgets, staff landing pages.
  - `Franchise/`: Multi-branch dashboards, menu synchronization, roaming staff, cross-branch inventory & PnL.
  - `Kitchen/`: Kitchen Display System (KDS), station routing, audio chimes.
  - `Layout/`: Sidebar navigation (`ImprovedSidebarNavigation.tsx`), operations headers, mobile bars.
  - `Orders/`: Table POS (`POSMode.tsx`), order list, order item cards, receipt printing.
  - `Platform/`: Super-admin management for restaurants, subscription tiers, and feature overrides.
  - `QSR/` & `QuickServe/`: High-velocity quick service POS interfaces.
  - `Reservations/` & `Rooms/`: Table reservations, hotel room management, housekeeping status.
  - `Staff/`: Shift management, time clock, biometric check-in, payroll and leaves.
  - `ui/`: Standardized shadcn/ui primitives (`button.tsx`, `dialog.tsx`, `table.tsx`, `toast.tsx`).

**`src/contexts/`:**
- **Purpose:** Cross-cutting state sharing without prop-drilling.
- **Contains:** React Context definitions and provider wrappers.
- **Key files:**
  - `AccessContext.tsx`: Manages active user permissions, role components, and plan feature flags.
  - `FranchiseContext.tsx`: Manages franchise organization context, accessible branches, and active branch switching.
  - `CurrencyContext.tsx`: Currency symbols, formatting rules, and exchange settings.
  - `NetworkStatusContext.tsx`: Online/offline connectivity detection and sync triggering.
  - `BrandingContext.tsx`: Dynamic restaurant branding, custom logo, theme colors.

**`src/hooks/`:**
- **Purpose:** Encapsulate stateful React Query queries, mutations, hardware listeners, and lifecycle hooks.
- **Contains:** Over 75 custom TypeScript hooks.
- **Key files:**
  - `useAuth.tsx`: Authentication state, user profile loading, sign-in/sign-out logic.
  - `useRestaurantId.tsx`: Active restaurant tenant ID resolution (supporting single restaurant and franchise branch switching).
  - `useFeatureGate.ts`: Granular feature entitlement check against active subscription plan.
  - `useOfflineCache.ts`: IndexedDB cache operations for offline order resilience.
  - `useRealtimeSubscription.tsx`: Supabase channel listener for live table mutations.
  - `usePushNotifications.tsx`: Capacitor push notification registration and FCM token sync.

**`src/pages/`:**
- **Purpose:** Top-level view components mapped directly to URL routes.
- **Contains:** Full-screen views loaded lazily via `React.lazy()` in `AppRoutes.tsx`.
- **Key files:**
  - `POS.tsx`, `QSRPos.tsx`, `QuickServePOS.tsx`: Point of sale views.
  - `Kitchen.tsx` & `KitchenTV.tsx`: Kitchen display system interfaces.
  - `Menu.tsx` & `RecipeManagement.tsx`: Menu engineering and recipe cost tracking.
  - `Financial.tsx`, `Analytics.tsx`, `Reports.tsx`: Financial reporting, P&L, GST reports.
  - `Franchise/FranchiseDashboard.tsx`: Multi-branch franchise overview.

**`supabase/`:**
- **Purpose:** Complete backend database schema, migrations, and serverless logic.
- **Contains:** SQL migrations and Deno Edge functions.
- **Key files:**
  - `migrations/`: Sequential migration files creating tables, triggers, functions, and RLS policies.
  - `functions/`: 46 Deno Edge Functions handling payments (Razorpay, Paytm), notifications (WhatsApp, Email), AI chat (Gemini), and reporting.

**`docs/`:**
- **Purpose:** Comprehensive developer architecture and reference documentation.
- **Key files:**
  - `docs/CODEBASE_CATALOG.md`: Route matrix, page list, hook inventory, and DB table list.
  - `docs/COMPONENTS_DETAILS.md`: Component directory breakdown and usage details.
  - `docs/FILE_REFERENCE_MAP.md`: File reference guide mapping routes, components, and permissions.
  - `docs/franchise_migration_analysis.md`: Complete franchise multi-branch system architecture and migration plan.

## Key File Locations

**Entry Points:**
- `src/main.tsx`: React DOM client entry point.
- `src/App.tsx`: Global providers (QueryClient, Theme, Tooltip, Auth, Access, Network) and root shell.
- `src/components/Auth/Routes.tsx`: Top-level router separating public vs authenticated paths.
- `src/components/Auth/AppRoutes.tsx`: Dashboard shell with sidebar layout and permission-guarded routes.

**Configuration:**
- `package.json`: Project dependencies, build scripts, and semantic version.
- `vite.config.ts`: Bundler settings, proxy rules, manual chunking, and Vitest configuration.
- `tsconfig.json`: TypeScript compiler options and `@/*` path mapping.
- `capacitor.config.ts`: Native Android configuration.
- `tailwind.config.ts`: Design system theme colors, spacing, and plugin registrations.
- `public/sw.js`: Service worker implementation for offline PWA caching.

**Core Logic & Utilities:**
- `src/utils/orderCalculations.ts`: Order math (subtotals, taxes, discounts, packaging).
- `src/utils/billCalculation.ts`: Bill splitting, round-offs, payment allocation, and UPI string generation.
- `src/constants/featureRegistry.ts`: 112 granular feature definitions and categories.
- `src/integrations/supabase/client.ts`: Supabase client configuration and proxy handling.

**Testing:**
- `src/tests/setup.ts`: Vitest test environment initialization and browser API mocks.
- `src/tests/App.test.tsx`: App shell render verification.
- `src/tests/PageValidation.test.tsx`: Route page loading and access control validation.
- `src/tests/PaymentFlow.test.tsx`: Payment flow simulation test.
- `src/tests/billFormatter.test.ts`: Bill calculation and formatting unit tests.

## Naming Conventions

**Files:**
- React Components & Views: `PascalCase.tsx` (`POSMode.tsx`, `KitchenDisplay.tsx`, `Orders.tsx`)
- Hooks: `camelCase.ts` or `camelCase.tsx` prefixed with `use` (`useOrders.tsx`, `useFeatureGate.ts`)
- Utilities & Libs: `camelCase.ts` (`orderCalculations.ts`, `billCalculation.ts`)
- Type Definitions: `camelCase.ts` (`orders.ts`, `menu.ts`, `rooms.ts`)
- Unit Tests: `*.test.ts` or `*.test.tsx` located under `src/tests/`

**Directories:**
- Feature/Component Domains: `PascalCase` (`src/components/Orders/`, `src/components/Kitchen/`)
- Functional Submodules: `camelCase` or `kebab-case` (`src/components/ui/`, `src/components/Orders/OrdersView/`)

## Where to Add New Code

**New Business Feature (e.g., Catering Management):**
- UI View: Create page in `src/pages/Catering.tsx`.
- Components: Create folder in `src/components/Catering/` with modular components.
- Data Hook: Create `src/hooks/useCateringData.tsx` using `useQuery` / `useMutation`.
- Types: Add domain interfaces in `src/types/catering.ts`.
- Feature Flag: Register feature key in `src/constants/featureRegistry.ts`.
- Route: Register route and `PermissionGuard` in `src/components/Auth/AppRoutes.tsx`.
- Sidebar: Add entry in `src/components/Layout/ImprovedSidebarNavigation.tsx`.
- Tests: Add test in `src/tests/components/Catering.test.tsx`.

**New Shared UI Primitive:**
- Add to `src/components/ui/<component-name>.tsx` adhering to shadcn/ui and Radix patterns.

**New Serverless Action / Integration:**
- Create function folder in `supabase/functions/<function-name>/index.ts`.
- Add local testing script or client invocation hook in `src/hooks/`.
