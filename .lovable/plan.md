# Android APK Diagnosis (read-only)

No files were changed. Findings below are split into **confirmed** (verified by reading the files listed) and **suspected risks** (plausible but not provable without a real Gradle/device run).

## Confirmed findings

### 1. Build breaks: theme references colors that do not exist
- Where: `android/app/src/main/res/values/styles.xml:7-9` uses `@color/colorPrimary`, `@color/colorPrimaryDark`, `@color/colorAccent`. `android/app/src/main/res/values/` contains only `ic_launcher_background.xml`, `strings.xml`, `styles.xml` — there is no `colors.xml`, and no other resource defines those names.
- Root cause: the standard Capacitor `values/colors.xml` is missing from the repo.
- Impact: AAPT2 resource linking fails (`resource color/colorPrimary not found`) — `assembleDebug` in CI never produces an APK.
- Fix: add `values/colors.xml` defining the three colors (Capacitor default `#3880ff` / `#3171e0` / `#3880ff`), or point the theme at literal colors.

### 2. Digital Asset Links package name does not match the app
- Where: `public/.well-known/assetlinks.json:6` declares `in.swadeshisolutions.app`; the app is `com.swadeshisolutions.app` (`android/app/build.gradle:4,7`, `capacitor.config.ts:4`).
- Impact: App Links verification fails; https deep links open in the browser instead of the app. The SHA-256 fingerprint listed also cannot be verified against a debug-only build.
- Fix: correct the package name and list the Play App Signing SHA-256.

### 3. `cap:sync` script points at a missing file
- Where: `package.json:13` runs `node scripts/sync-version.js && npx cap sync`; `scripts/` contains only `convert_icons.ps1` and `resize_screenshot.ps1`.
- Impact: `npm run cap:sync` exits before syncing. (CI at `.github/workflows/android-build.yml:34` calls `npx cap sync` directly, so CI is unaffected.)
- Fix: restore the script or change `cap:sync` to plain `npx cap sync`.

### 4. Version drift between web and native
- Where: `package.json:4` = `1.0.30`; `android/app/build.gradle:10-11` = `versionCode 10029` / `versionName "1.0.29"`.
- Impact: shipped APK reports a stale version; any in-app update/version check against `public/version.json` can mis-fire.
- Fix: keep them in sync (this is what the missing `sync-version.js` was for).

### 5. No release signing / release build path — not Play Store ready
- Where: `android/app/build.gradle:19-24` has a `release` block with `minifyEnabled false` and no `signingConfigs`/`signingConfig`. `.github/workflows/android-build.yml:40,46` builds and uploads only `assembleDebug` / `app-debug.apk`.
- Impact: no signed, uploadable artifact; Play Console requires an **AAB** (`bundleRelease`), signed, with shrinking usually enabled. A debug APK cannot be published.
- Fix: add a keystore-backed `signingConfigs.release` fed by CI secrets, add a `bundleRelease` job, enable `minifyEnabled` + shrinkResources with Capacitor-safe ProGuard rules (`proguard-rules.pro` is currently the untouched template).

### 6. Capacitor config declares plugins that are not installed
- Where: `capacitor.config.ts:7-18` configures `SplashScreen` and `StatusBar`; `package.json:19-25` installs only `@capacitor/android`, `app`, `cli`, `core`, `local-notifications`, `push-notifications` (+ `@aparajita/capacitor-biometric-auth`). `android/app/capacitor.build.gradle:12-16` confirms only those four native modules.
- Impact: splash duration/colour and status-bar styling are silently ignored at runtime. The launch theme still uses `@drawable/splash` (`styles.xml:20-22`), which exists, so launch itself works — but the splash never auto-hides via the plugin.
- Fix: install `@capacitor/splash-screen` and `@capacitor/status-bar`, or drop the dead config.

### 7. Bluetooth printing depends on a Cordova plugin that is not wired into the Android build
- Where: `package.json:68-69` lists `cordova-plugin-bluetooth-serial` and `cordova-plugin-android-permissions`; `src/services/nativePrinterBridge.ts:143` reads `window.bluetoothSerial`. But `android/app/capacitor.build.gradle:11-17` (regenerated by `cap sync`) lists no Cordova plugin dependencies, and `android/.gitignore` excludes `capacitor-cordova-android-plugins` while `android/settings.gradle:2-3` includes that module.
- Impact: on a fresh CI checkout the `:capacitor-cordova-android-plugins` module directory only exists after `cap sync` — which CI does run, so the build is fine; however the committed `capacitor.build.gradle` shows the Cordova bridge was last synced with **no** Cordova plugins registered, which matches the runtime error path "bluetoothSerial plugin not available". Bluetooth thermal printing is likely non-functional in the built APK.
- Fix: verify `npx cap sync` picks up the Cordova plugins (they must be Capacitor-compatible Cordova plugins), or replace with a maintained Capacitor BLE/serial plugin.

### 8. TCP printer plugin: sockets leak on failure
- Where: `android/app/src/main/java/com/swadeshisolutions/app/TcpPrinterPlugin.java:55-72` and `:94-100` — `socket.close()` is only reached on the success path; any exception during `connect`/`write` skips it (no `try-with-resources` / `finally`).
- Impact: repeated failed prints leak file descriptors; over a long shift this can exhaust FDs and destabilise the app.
- Fix: use `try (Socket socket = new Socket())` or a `finally` block.

### 9. Permissions declared beyond what the code needs
- Where: `android/app/src/main/AndroidManifest.xml:57-63` declares `BLUETOOTH_ADVERTISE`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` with no `maxSdkVersion`.
- Impact: `BLUETOOTH_ADVERTISE` is unused (the app never advertises). Fine/coarse location triggers a Play Console location-permission declaration and a Data Safety disclosure, and shows a scary runtime prompt — for Bluetooth Classic SPP on Android 12+ it is not required (`BLUETOOTH_SCAN` with `neverForLocation` is already set at line 57).
- Fix: drop `BLUETOOTH_ADVERTISE`; scope location to `android:maxSdkVersion="30"` or remove it.

### 10. `logcat_push.txt` is empty
- Where: `logcat_push.txt`, 0 bytes.
- Impact: no runtime evidence available; push-notification behaviour on device could not be verified from this repo.

## Suspected / lower-confidence risks

- **CI dependency install is non-reproducible.** `.github/workflows/android-build.yml:19` uses `npm install` while `package-lock.json` exists and the web workflow uses `npm ci` (`.github/workflows/cloudflare-pages.yml`). Lockfile drift can change the Capacitor version between web and Android builds.
- **CI Node version mismatch.** Android workflow uses Node 22, Cloudflare workflow Node 20 — the `dist/` bundled into the APK may differ from the deployed web build.
- **Cleartext / local network.** `capacitor.config.ts:22` sets `allowMixedContent: false` and the manifest has no `usesCleartextTraffic`/network-security-config. Raw `java.net.Socket` printing on port 9100 is unaffected, but any `http://` LAN call made from the WebView will be blocked on Android 9+.
- **Android 13+ local-network discovery.** Printer discovery over LAN on Android 14/15 (targetSdk 36) may require `NEARBY_WIFI_DEVICES` depending on the discovery method used; not declared.
- **FileProvider paths are broad.** `res/xml/file_paths.xml` exposes `external-path` and `cache-path` at `.` (whole roots) — wider than needed for invoice/PDF sharing.
- **Firebase config committed.** `android/app/google-services.json` is checked in (project `fir-project-e1e79`). The API key there is a public client key, so this is low severity, but the Firebase project ref differs from the Supabase-centric backend — worth confirming FCM sender is the one the push edge function targets.
- **`google-services` plugin applied conditionally** (`android/app/build.gradle:47-53`) — if `google-services.json` is ever missing, the build silently succeeds with push notifications broken rather than failing loudly.
- **Build tooling versions** AGP 8.13.0 (`android/build.gradle:10`) + Gradle 8.14.3 wrapper + Java 21 + compileSdk/targetSdk 36 are self-consistent; not verified against an actual Gradle run in this sandbox.
- **No instrumentation of launch path verified.** `MainActivity.java:9` registers `TcpPrinterPlugin` before `super.onCreate` — this is the correct Capacitor pattern; no issue found, listed for completeness.

## Suggested order of remediation

1. Add `values/colors.xml` (unblocks the build).
2. Fix `assetlinks.json` package name; add release signing + `bundleRelease` CI job.
3. Reconcile version numbers and the `cap:sync` script.
4. Install or remove the SplashScreen/StatusBar plugins; resolve the Cordova Bluetooth plugin situation.
5. Harden `TcpPrinterPlugin` socket handling; trim permissions before Play submission.
